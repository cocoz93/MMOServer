## 이 문서를 쓰는 법 (루프 작업 규칙)

**이 문서가 진행 상태의 정본이다.** 시작할 때 여기부터 읽고, 체크가 안 된 첫 페이즈 **하나만** 한다.

### 페이즈 하나를 끝내는 절차

1. **작업** — 그 렌즈로 6페이지를 전부 훑는다
2. **판정** — 페이즈에 붙은 기준을 실제로 확인한다
3. **고치기** — 어긋난 것은 **그 자리에서 노션을 고친다.** 목록만 만들고 넘어가지 않는다
4. **자가검증** — 아래 세 가지를 이 순서로 확인한다
5. **기록** — `- [ ]` → `- [x]`, 찾은 것과 고친 것을 아래 「발견」에 적는다
6. **커밋** — 개조식, 트레일러 없음, **push 안 함**

### 자가검증 — 감사에는 이게 더 필요하다

작성할 때의 자가검증은 "내가 쓴 게 맞나"였다. **감사의 자가검증은 "내가 잡은 게 맞나"다.**
감사는 없는 문제를 만들어내기 쉽고, 그렇게 만든 지적은 멀쩡한 문서를 망가뜨린다.

- **① 잡은 것이 진짜인가 (오탐 거르기)** — 지적마다 근거를 **다시** 확인한다.
  코드 위치를 댔다면 그 줄을 실제로 다시 열어보고, 명령 결과를 댔다면 다시 돌린다.
  **근거가 "그래 보인다"뿐이면 지적을 취소한다** — 취소도 정상적인 결과다
- **② 고친 것이 제대로 됐는가** — 고친 자리를 다시 대조한다.
  노션 수정은 `old_str` 매칭이라 **엉뚱한 곳이 바뀌었을 수 있고**, 고치면서 새 오류를 넣었을 수도 있다
- **③ 정말 다 봤는가 (범위 누락)** — 이 렌즈의 대상이 6페이지 전부였는지 확인한다.
  **"3페이지까지 보고 문제없어서 나머지도 그러려니 한" 것이 아닌지**가 핵심이다.
  대상 개수를 세어 기록한다 (예: 인용 N개 중 N개 대조)

*자가검증에서 지적이 취소되거나 새로 나오면 그것도 「발견」에 적는다 — 감사 자체의 정확도가 기록으로 남아야 한다*

### 감사 규칙 — 억지로 잡지 않는다

- **근거 없이 "틀렸다"고 하지 않는다.** 코드 위치·명령 결과·원본 문서 중 하나를 대야 한다
- **문제가 없으면 "문제 없음"을 명시한다.** 렌즈 하나를 통째로 통과하는 것은 정상이다
- 재현할 수단이 없는 의심은 **「관측대기」**로 남긴다 (결함으로 단정하지 않는다)
- **표현 취향은 지적 대상이 아니다.** 사실이 틀렸거나, 읽고 이해가 안 되거나, 근거가 없을 때만 잡는다

**실제로 돌려 보니 그 원본 기록이 틀렸다.**

- `setarch` 없이(못 뜸, `FATAL: unexpected memory mapping`) → **rc=66** (3회 재현)

*A2의 "원본과 다르면 재본다"가 여기서도 답이었다. 그때는 objdump를 재봐서 지적을 취소했는데,

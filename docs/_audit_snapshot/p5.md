	**찾아낸 것을 숨기지 않는다.** 도구가 경고를 뱉은 것, 판정 방법이 틀렸던 것, 나중에 다시 훑어 잡은 것까지 그대로 적는다. 검증의 값어치는 초록불이 아니라 **무엇을 어떻게 의심했는가**에 있다.

## 경합을 억지로 만들어서도 돌렸다
일반 실행에서 통과하는 것으로는 부족하다. 락프리 자료구조의 문제는 **타이밍이 나쁠 때만** 드러난다.
그래서 `LF_RACE_HOOK` 증폭 빌드 — CAS 주변에 지연을 넣어 경합 창을 억지로 벌리는 빌드 — 로 6종을 다시 돌렸다. **전부 rc=0**(`repro` 30초 / `cons` / `fl` 20초 / `tls` 20초 / `qbuf` 15초 / `tlsleak`).
<callout icon="🕳️" color="red_bg">
	**여기서 하마터면 속을 뻔했다 — 증폭이 실제로 걸렸는지부터 확인해야 한다.**
	증폭 빌드가 통과했다는 것만으로는 아무 의미가 없다. **매크로가 안 걸렸으면 그냥 일반 빌드를 돌린 것이고, 그래도 초록불이 뜬다.**
	테스트가 스스로 찍는 라벨로 확인했다 — 일반은 `RACE_HOOK OFF - 대조군`, 증폭은 `RACE_HOOK ON`. 이 줄이 정본이다.
</callout>
<callout icon="⚠️" color="orange_bg">
	같은 함정이 `qbuf`에도 있다. 이 테스트는 검증 조건이 한 번도 발생하지 않으면 `rc=1`("테스트 무효")을 낸다. **rc=0이라는 것이 곧 "유효한 실행이었다"는 뜻**이라, 그냥 통과가 아니라 그 구분까지 봐야 한다.
</callout>
# 2. TSan과 ASan — 보고를 어떻게 읽었나 ★
리눅스에는 Windows에 없던 도구가 있다. 스레드 경합 검출기(TSan)와 메모리 검사기(ASan)를 돌려봤다.
**TSan은 모든 테스트에서 경합을 보고했다.** 그냥 넘길 수 없는 결과다.
## 이식 탓인지부터 갈랐다
의심할 곳이 분명했다 — 16바이트 CAS를 옛 `__sync`로 쓴 것(→ [2. 락프리를 리눅스로](https://app.notion.com/p/3b216a0b9f5981e9b81fe8a20bd89ad3) 3장). TSan은 `__atomic`은 이해하지만 `__sync`는 잘 못 읽는다고 알려져 있다.
그래서 **`__atomic`****으로 바꾼 판을 따로 만들어 대조**했다.

## 그럼 무엇이 원인인가 — 정직하게
보고의 최다 패턴이 `Read of size 8` **52건**이었다. 락프리가 CAS 직전에 하는 **평문·****`volatile`**** 스냅샷 읽기**가 다른 스레드의 원자 쓰기와 겹치는 것이다. 이 알고리즘의 구조 자체다.
<callout icon="🚫" color="red_bg">
	**"오탐"이라고 쓰고 싶지만, 정직하게는 C++ 표준상 실제로 정의되지 않은 동작이다.**
	`volatile` 읽기는 원자성도 순서도 보장하지 않는다. x86-64에서 자연 정렬된 8바이트 로드가 하드웨어적으로 원자적이고, `volatile`이 컴파일러 재배치를 막아 **실무적으로 도는 것**이다.
	근본 해결은 `volatile`을 `std::atomic`(relaxed)으로 바꾸는 것인데, 그건 자료구조 재설계라 **포팅 범위 밖**이다. 여기서 중요한 것은 **리눅스에서 새로 생긴 위험이 아니라는 점** — Windows에서도 같은 코드가 같은 방식으로 돌고 있었고, 다만 그걸 볼 도구가 없었을 뿐이다.
</callout>
## ASan
`fl`은 **누수 0**. TLS 경로에서만 검출됐다(`tlsleak` 2,567,680바이트/40건, `tls` 128,384바이트/2건). 이건 테스트가 원래 "누수 확인(알려진 한계)"로 보고하던 항목이고 **Windows에서도 같은 보고가 난다.**
<callout icon="💡" color="gray_bg">
	**예고가 하나 빗나갔다.** 힙 API를 `malloc`으로 바꾸면서 "`HeapDestroy`의 일괄 회수가 사라져 누수로 잡힐 것"이라고 미리 적어뒀는데, `fl`에서는 안 나타났다.
	그 테스트가 **모든 노드를 프리리스트로 되돌리고 끝나기** 때문이다. 사용 중 노드를 남긴 채 소멸하는 경로에서만 의미가 있는 예고였다. 예고를 적어둔 덕분에 "왜 안 나왔지"를 바로 설명할 수 있었다.
</callout>
<callout icon="🕳️" color="red_bg">
	**TSan은 WSL2에서 대개 시작조차 못 한다.**
	`FATAL: unexpected memory mapping`으로 죽는다(ASLR 충돌). 그런데 **종료 코드는 66** — `setarch -R`로 제대로 띄워 경합을 찾았을 때와 **똑같은 값**이다(실측). rc만 봐서는 "못 떴다"와 "떴는데 경합이 있다"가 구분되지 않는다.
	그래서 처음 세 테스트를 "TSan을 돌렸다"로 셀 뻔했다. 표준 출력을 안 읽었으면 모르고 넘어갔을 것이다 — **이 검사 도구들은 종료 코드만으로 판정하면 안 된다.**
	`setarch -R`로 ASLR을 끄고 돌려야 한다.
</callout>
# 3. 크로스 OS 통신 — 진짜 클라이언트로
가장 강한 증거는 **Windows에서 빌드된 기존 부하 클라이언트가 리눅스 서버에 그대로 붙는 것**이다. 새로 만든 도구끼리 맞춰보는 게 아니라, 손대지 않은 쪽이 붙어야 와이어 포맷이 맞다는 뜻이 된다.
붙이는 데는 따로 손볼 것이 없었다. 계획서에는 "WSL2는 기본 NAT라 밖에서 안 붙는다"고 적어 뒀는데, **그 전제가 틀렸다** — `localhostForwarding`이 기본으로 켜져 있어 **같은 PC의 Windows 쪽에서는 `localhost`로 그냥 닿는다.** `netsh portproxy`가 필요 없었다. (다른 PC에서 붙이려면 여전히 설정이 필요하다 — WSL IP가 재부팅마다 바뀐다)

# 4. Windows 회귀 빌드 — 안 깨뜨렸는가
전송 경계를 OS 중립으로 만들면서 **기존 Windows 두 팔의 구현도 고쳤다.** 그러니 "리눅스가 되는가"만큼 "Windows가 그대로인가"가 중요하다.

<callout icon="⚠️" color="orange_bg">
	**증분 빌드로는 경고를 못 본다.** 재컴파일되지 않은 번역 단위의 경고는 애초에 출력되지 않기 때문이다.
	한 번은 **리눅스** 증분 빌드 결과를 "경고 0"으로 기록했다가, 클린으로 다시 재니 **알려진 경고 2건**(`-Winvalid-offsetof`, 락프리 원본의 성질)이 있었다. 억제하지 않고 남겼다 — **리눅스 기준선은 "경고 0"이 아니라 "알려진 2건"이다.** 위 표의 경고 0은 Windows 쪽 숫자라 서로 부딪치지 않는다.
</callout>

# 6. 아직 못 한 것
<callout icon="🎯" color="yellow_bg">
	**여기까지는 전부 정확성이다.** 성능 비교는 아직 안 했다.
	WSL2로는 의미 있는 비교가 안 된다 — 가상화와 NAT 오버헤드 때문에 Windows 쪽이 이기는 것이 당연해진다. **실기 리눅스나 클라우드가 필요하다.**
	락프리 테스트 6종 전량 대조도 **측정 보류** 상태다. 재검증에서는 빌드 회귀만 확인했다.
</callout>

## 직접 확인해 보기
**① 락프리 테스트를 직접 돌려보기** — 빌드부터 한다. 실제로 확인한 명령이다.
```bash
cd /mnt/c/Users/USER/Desktop/MyGit/LockFree/LockFree_Test
g++-13 -O2 -mcx16 -std=c++17 -pthread TestCode.cpp -o /tmp/lftest
/tmp/lftest fl 8 10 ; echo "rc=$?"
# [EXIT] fl = 위반 미검출 / rc=0
```
인자 없이 실행하면 메뉴가 뜬다. 위 표의 6종을 같은 인자로 주면 Windows 결과와 맞대볼 수 있다.
**② TSan을 쓸 거라면 반드시 ****`setarch -R`**
```bash
g++-13 -fsanitize=thread -O1 -mcx16 -std=c++17 -pthread TestCode.cpp -o /tmp/lftsan
setarch -R /tmp/lftsan fl 4 5          # ASLR을 켜 두면 20회 중 18회 못 떴다
/tmp/lftsan fl 4 5 ; echo "rc=$?"      # rc=66 — 못 떴을 때도, 떴는데 경합을 찾았을 때도 같은 값이다
```
**③ 증폭이 실제로 걸렸는지** — 출력 첫머리의 라벨을 본다.
```plain text
RACE_HOOK OFF - 대조군     ← 일반 빌드
RACE_HOOK ON               ← 증폭 빌드
```
**④ Windows 회귀 빌드는 반드시 클린으로.** 증분은 재컴파일 안 된 파일의 경고를 아예 안 보여준다.

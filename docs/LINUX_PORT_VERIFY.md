# 리눅스 포팅 — 완료 페이즈 재검증

이미 `- [x]`로 닫은 페이즈들을 **다시 확인**하는 문서. 진행 계획은 `LINUX_PORT_PLAN.md`가 정본이고,
이 문서는 그 기록이 **지금도 사실인지** 만 본다.

## 왜 하는가

페이즈를 닫을 때는 그 시점에 통과했지만, **뒤 작업이 앞을 깨뜨릴 수 있다.**
실제로 4-I의 회귀빌드에서 Windows 파손 3건이 나왔다 — 4-C에서 넣은 `Platform.h`의 `<WinSock2.h>`가
`sockaddr` 재정의를 일으켰고, 그건 4-D~4-H 내내 드러나지 않았다. 리눅스만 보고 있었기 때문이다.

## 검증 규칙

**한 번에 한 그룹만.** 체크가 안 된 첫 그룹을 처리하고 결과를 적는다.

각 그룹에서 보는 것은 셋이다.

1. **판정 재실행** — 그 페이즈의 판정 기준을 실제로 다시 돌린다
2. **근거 대조** — 계획서에 적은 파일·줄번호·개수·수치가 지금 코드와 맞는지 확인한다
3. **회귀 확인** — 뒤 작업이 이 페이즈의 결과를 깨뜨리지 않았는지 본다

결과는 `- [x]`로 바꾸고 **확인한 수치와 함께** 적는다. 어긋난 것이 나오면
`LINUX_PORT_PLAN.md` 쪽 기록도 함께 고친다(그쪽이 정본이므로).

### 지금은 하지 않는 것

**CPU를 오래 무는 검증은 보류한다** — PC를 쓰는 중이면 결과가 노이즈를 먹는다.
해당 항목은 `[측정보류]`로 표시했고, PC가 한가할 때 5단계 측정과 함께 몰아서 한다.

## V2. LockFree 이식 (1단계)

- [x] **V2** 재확인 — **통과 (2026-08-04). 회귀 없음**

  | 항목 | 결과 |
  |---|---|
  | 어댑터 제공 | **17종 전부 존재** (원자연산 5 · 힙 5 · 정렬 2 · TLS 4 · SwitchToThread 1) |
  | 1-A 개수 대조 | **Interlocked 18곳 / CAS128 7곳 — 계획서와 정확히 일치** |
  | `-mcx16` 방어막 | 있음 → exit 0 / 없음 → **`#error` 발동** (살아 있다) |
  | 인라인 CAS | `lockfree_headers_check` **19개** / `mmo_server` **18개**, 외부 CAS 호출 **0** |
  | libatomic 의존 | 두 산출물 모두 **0** |
  | **타입 충돌 회귀** | `LONG64`=`long long`, `ULONG`=`DWORD`=`uint32_t` — **`Platform.h`와 `LockFreeCompat.h`가 동일** |

  - **가장 중요한 확인은 `mmo_server`에도 인라인 CAS 18개가 남아 있다는 것**이다. 1단계에서 `lockfree_headers_check`로만 봤던 것이, 4단계에서 만든 서버 본체에서도 유지된다 — `__sync` 전환이 실제 서버 바이너리까지 살아 있다
  - 4-C에서 `Platform.h`에 같은 이름의 타입을 넣을 때 한 번 `conflicting declaration`이 터졌던 자리다. 지금은 양쪽이 같은 타입이라 문제없다

  > **측정 방법 실수 하나 — 처음엔 개수가 안 맞았다**
  > `*.h`로 훑었더니 Interlocked 24 / CAS128 8이 나왔다. `LockFreeCompat.h`가 같은 디렉토리에 있어 **어댑터 정의 자신이 카운트에 섞인** 것이었다. 1-A의 대상은 자료구조 헤더 4개뿐이므로 그것만 다시 세어 18/7을 확인했다. **코드가 바뀐 게 아니라 내 측정이 틀렸다.**
  - `LockFreeCompat.h`가 **어댑터 5종 + 힙 5종 + 정렬 2종 + TLS 5종**을 여전히 제공하는지
  - `-mcx16` **없이** 빌드하면 `#error`가 나는지 (방어막이 살아 있는지)
  - 산출물에 **인라인 `cmpxchg16b`**가 있고 **libatomic 호출이 0**인지
  - 계획서 1-A의 개수(Interlocked 18곳·CAS128 7곳)가 지금도 맞는지
  - **회귀 관점**: 4-C에서 `Platform.h`에도 `ULONG`/`DWORD`/`LONG64`를 넣었다 — `LockFreeCompat.h`와 **같은 타입인지**(다르면 conflicting declaration이 다시 난다)

> 앞 편(5a) 요약: 세션 타임아웃을 선형 스캔 대신 타이밍 휠로 처리한다. 외부 스레드는 Lock-Free 큐에 Register/Refresh/Unregister를 넣고, 타이머 스레드만 휠을 만진다(단일 Writer라 락 불필요). 인덱스 재사용은 sessionId 매칭으로 걸러낸다. 이 편은 **휠이 실제로 어떻게 생겼고 왜 그 숫자인가**를 다룬다.

## 휠의 물리적 구조

휠은 배열을 **두 벌** 쓰고, 찌르는 첨자가 서로 다르다.

- **슬롯 배열** `_slots[61]` — 휠의 칸. **cursor로만** 접근한다(세션 인덱스로 슬롯을 찾는 경로는 없다).
- **노드 배열** `_nodes[maxSessions]` — 세션마다 하나씩 사전 할당. **세션 인덱스로** O(1) 접근하므로 동적 할당이 없다.

노드 배열은 서버의 세션 객체 배열(`_sessions`)과 **별개**다 — 같은 index로 짝지어질 뿐, 휠은 세션 객체를 모르고 숫자 두 개(index, sessionId)만 받는다. 그 index도 조회로 얻는 게 아니라 `sessionId >> 48`로 뽑는다(상위 16비트가 index · `CSession::ExtractIndex`).

> [그림: 06_wheel_structure]

각 슬롯의 실체는 **더미 하나짜리 원형 이중 연결 리스트**다. `Slot`에 든 게 더미 노드 하나뿐이라 슬롯이 곧 더미이고, 노드 실물은 전부 `_nodes[]`에 있다 — 슬롯 이동은 노드가 옮겨 가는 게 아니라 **어느 실에 꿰이느냐**가 바뀌는 것이다.

- **원형** — `head.prev`가 곧 꼬리라 꼬리 삽입이 O(1)
- **이중** — 중간 노드도 앞을 알아 양옆만 이어붙이면 빠진다
- **더미** — "비었나 / 내가 첫 번째인가" 분기가 사라진다

> **왜 순회가 없나 — 노드를 "찾지" 않고 "집는다".**
> 리스트를 훑어 찾는 게 아니라 `_nodes[index]`로 바로 집고, 노드가 `prev`·`next`를 들고 있어 양옆을 이어붙여 O(1)로 뺀다. (이중리스트) — Refresh·Unregister가 노드 위치와 무관하게 항상 O(1)인 이유다. (순회가 남는 곳은 만료 슬롯을 통째로 비우는 Tick뿐.)
> 노드의 `slotIndex`는 슬롯을 찾아가는 번호가 아니다. 제거가 양옆 포인터만으로 끝나므로, 이 값은 -1인지로 **등록 여부**를 가리는 데 쓴다.

## Tick 동작 — cursor가 시계처럼 전진한다

매 tick마다 타이머 스레드가 수행하는 동작 (**운영값 1초**, 아래 예시만 설명용 5초):

1. **Drain** — Lock-Free 큐에서 요청을 모두 꺼내 휠에 반영
   - Register: 노드(=세션)를 현재 cursor 슬롯에 삽입 (한 바퀴 후 만료)
   - Refresh: 노드를 기존 슬롯에서 빼고, 현재 cursor 슬롯으로 이동
   - Unregister: 노드를 슬롯에서 제거
2. **Tick** — cursor를 한 칸 전진시키고, 해당 슬롯의 **모든 노드를 만료 처리**

> 핵심 아이디어: 노드가 삽입된 슬롯에 cursor가 **한 바퀴 돌아 다시 도달하면** 그 세션은 타임아웃된 것이다. 그 사이에 Refresh가 오면 노드가 다시 cursor 슬롯으로 옮겨지므로 만료 시점이 리셋된다.

> **Tick의 순회는 헛걸음이 없다.** 훑는 노드가 곧 끊을 대상이라, 전체를 비교해 몇 개를 골라내는 선형 스캔과 달리 휠은 그 몇 개만 훑는다.
> 게다가 정상 세션은 하트비트(20초)마다 다른 칸으로 옮겨 가므로, cursor가 한 바퀴(60초) 돌아 도착했을 때 남은 건 **그 사이 신호가 없던 세션**뿐이다.

## 구체적 예시 (설명용 축소 모델) — 60초 타임아웃, 5초 tick, 슬롯 13개

> [그림: 07_refresh_reset]

```
시각 0초   cursor=0  │ Session A 접속 → 삽입은 tick 직전 cursor 자리인 Slot 12
시각 5초   cursor=1  │ Slot 1 처리 (비어있음)
시각 10초  cursor=2  │ Slot 2 처리 (비어있음)
...
시각 30초  cursor=6  │ Session A가 패킷 수신 → Refresh
                     │   Slot 12에서 제거 → tick 직전 cursor 자리인 Slot 5에 재삽입
...
시각 55초  cursor=11 │ Slot 11 처리 (비어있음)
시각 60초  cursor=12 │ Slot 12 처리 — Refresh가 없었다면 여기서 A가 만료됐다
시각 65초  cursor=0  │ Slot 0 처리 (비어있음)
...
시각 85초  cursor=4  │ (비어있음)
시각 90초  cursor=5  │ Slot 5 처리 — Session A 만료! (30초 + 60초 = 90초)
                     │   → RequestDisconnectSession(A) 호출
```

Session A는 마지막 활동(30초) 이후 정확히 60초가 지난 90초 시점에 만료된다. Refresh가 없었다면 0초 + 60초 = 60초에 만료되었을 것이다.

## 슬롯 수 계산과 +1 보정

> [그림: 02_slot_plus_one]

```
slotCount = ceil(timeoutSec × 1000 / tickIntervalMs) + 1
```

타이머 스레드의 매 루프는 **Drain → Tick** 순서로 실행된다.

1. Drain에서 노드를 현재 cursor 슬롯(C)에 삽입
2. 직후 Tick이 cursor를 C+1로 전진 → C는 건너뜀
3. cursor가 다시 C에 도달하려면 `slotCount - 1` tick 필요

따라서 `slotCount - 1 = ceil(timeout / tick)` → **slotCount에 +1을 더해야 정확한 timeout이 보장**된다.

**운영값** (timeout=60초, tick=1000ms):
- `slotCount = 60 + 1 = 61`
- 실제 만료 = 60 tick × 1초 = **60초** ✓

**설명용 축소 모델** (timeout=60초, tick=5000ms):
- `slotCount = 12 + 1 = 13`
- 실제 만료 = 12 tick × 5초 = **60초** ✓

## Tick 해상도 선택

> [그림: 03_tick_resolution]

**서버 운영값 = 1,000ms (1초) · 슬롯 61개** — 세션 타임아웃 60초 기준. (`IOCPServer.h`의 `TIMER_TICK_INTERVAL_MS = 1000`을 `CTimingWheel::Init`에 전달.) 타이밍휠 자체의 기본 인자도 1초(`tickIntervalMs = 1000`)이고, 서버는 이 값을 `Init`에 명시적으로 넘긴다. *위 「구체적 예시」의 코드만 슬롯 61개를 글로 따라가기 어려워 5초 tick · 13슬롯으로 축소했다. 그림은 운영값(1초 · 61슬롯) 그대로고, 동작 원리는 둘 다 같다.*

> 해상도의 하한은 **죽은 세션을 얼마나 늦게 알아채도 되는가**가 결정한다.
> 위 +1 보정 때문에 만료는 항상 타임아웃 **이후**다(60초 ~ 60초+해상도). 해상도를 낮춰도 살아 있는 세션이 먼저 끊기는 일은 없다.
> 대신 이미 죽은 세션의 자리를 붙들고 있는 시간이 해상도만큼 길어진다.

| 해상도 | 슬롯 수 | wake-up/초 | 실제 만료 (마지막 패킷 기준) | 판정 |
| --- | --- | --- | --- | --- |
| **1,000ms** | **61개** | **1.0** | **60~61초** | **✅ 채택 (서버 운영값)** |
| 5,000ms | 13개 | 0.2 | 60~65초 | 이 문서 예시의 축소 모델 |
| 10,000ms | 7개 | 0.1 | 60~70초 | 경계선 (감지가 최대 10초 늦음) |
| 15,000ms | 5개 | 0.07 | 60~75초 | 위험 (감지 15초 지연 · 만료가 5슬롯에 뭉침) |

하트비트 20초, 타임아웃 60초 기준: 정상 세션은 20초마다 Refresh가 오므로 60초 만료선에 닿지 않는다. 네트워크 지연이 40초 넘게 벌어지지 않는 한 **오탐으로 끊기는 경로 자체가 없다.**

해상도를 더 낮출수록 슬롯 수·wake-up 횟수가 줄어 유리하지만, 죽은 세션을 붙들고 있는 시간이 그만큼 길어진다 — 10초 tick이면 최대 70초, 15초면 75초까지 그 자리가 안 빈다.
반대로 5초가 아니라 1초를 고르면서 해상도는 좋아졌지만, 대가로 wake-up이 초당 0.2회 → 1회로 5배 늘었다.

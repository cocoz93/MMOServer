**T2의 60초 지연** <sub>(2차 [13])</sub> — 클라 INI(`ClientCount`·`ClientsPerThread`)는 모니터링 스택 기동(`setup.ps1` + 3개 프로세스 + `Start-Sleep 5`) **뒤에** 써진다. 발사 직후 읽으면 옛 값이 잡혀 오탐 정지가 난다.

**r1↔r2 정합을 3지표로 한정** <sub>(2차 [14])</sub> — 대조 지표는 **송신량 · 배치 바이트 · 워커max**. 기준선 RMB2조차 `dummy_loop_p99`가 19.35 ↔ 19.55(**+1.03%**)로 ±1%를 넘었다. 전 지표에 ±1%를 걸면 정상 런이 걸린다.

**T5/T7이 T3에서 상속하는 것은 구조 검사뿐** <sub>(2차 [15])</sub> — T3의 환경 정합 게이트는 **RMB2(K3 기준선) 대조**다. K4·K5는 워커max가 정당하게 0.90 → 0.68 → 0.54로 달라지므로, 이 게이트를 문자 그대로 물려받으면 워커max가 상시 1표를 채워 2-of-3 정지 조건이 과하게 쉽게 성립한다.

**기대 max에 밴드를 쓰는 이유** <sub>(초견 경미 5)</sub> — 합 불변 가정은 실측과 어긋난다. 5,600에서 K3 합 2.42 → K4 합 **2.57(+6.2%)**이었다. 6,600 K3 합 2.7068 기준으로 K4 합이 2.71~2.87 사이면 max는 0.68~0.72이므로 밴드로 잡는다.

### 7-2. 양자화 페이지 `3bb16a0b9f598049a873fad65fc1aeff`

**6,600으로 교체**
- §3 실측 표 **8행 전부 — 회선 환산 행 포함** <sub>(중대 2)</sub>. 6,600에서는 `140% → 109%`가 되고, 그게 사실이다

**유지**
- **§1 회선 부하 표는 5,600 기준** — 문제 제기 역할. 여기에 `105% → 82%`(수용 불가 → 수용 가능) 서사가 살아 있다
- §5 결론 콜아웃의 회선 한 줄 `105% → 82%`도 **5,600 기준으로 유지**
- §4 천장 사다리 (별도 측정이라 불변)

**필수 라벨** — 한 페이지에 두 부하점이 공존하므로 각 표·문장에 `(동접 5,600 기준)` / `(동접 6,600 A/B)` 명시. §3 진단 콜아웃의 details summary는 두 기준 병기 <sub>(경미 14 / 3차)</sub>
